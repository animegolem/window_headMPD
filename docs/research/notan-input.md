Q1 — WINDOWING: hybrid, with phase-1 commitments that are pure de-hardcoding. Introduce a SkinWindow abstraction with binding as a per-instance property and no binding-specific types in its contract. This seam must exist anyway — .wms views are created/destroyed at runtime with script-computed geometry, so the interpreter can never talk to Tauri directly — which makes deferring the Winamp decision free, not speculative. Phase 1 binds SkinWindow to REAL Tauri WebviewWindows, because for WMP that's corpus fact, not analogy: sampled skins have up to 5 simultaneous views, and per-view Keep-on-Top is native WMP semantics your per-window menu already expresses. Phase 2's Winamp cluster is probably the opposite binding — an internal compositor in one host window, Webamp-style, where snap/dock/windowshade is integer math in skin pixels and one GL context — but decide that WITH Winamp code in hand; freeze in phase 1 only what WMP exercises (open/close, bounds, setLayout/view swap, startDrag, mask rebuild, persistKey) and make snap/dock/group hooks an explicit phase-2 contract extension. Concrete phase-1 work the panel verified against your code: (a) generalize clickthrough.rs — HitState becomes masks: HashMap keyed by window.label() and capture: Option<String> naming the capturing window; your current global AtomicBool would make EVERY window clickable during any slider drag and steal clicks that should fall through neighbors; (b) a WebviewWindowBuilder factory reusing your proven tauri.conf.json flag block with ?view=<id> — per-webview JS context gives you WMP's per-view scriptFile semantics for free; (c) make mask freshness structural: rasterizeMask in the widget kit invalidated by MutationObserver + transitionend into a rAF-debounced dirty flag, so the stale-mask class dies once instead of per callsite; (d) audio_subscribe fans out to Vec<Channel<Frame>>, dead channels dropped on send error; (e) restore order main-window-first with aux positions clamped to visible frames. ORACLE: define goldens as skin-space composition rasterizations diffed per-SkinWindow rect, never OS screenshots — that makes the oracle binding-agnostic, so the same harness validates Headspace today, a 5-view skin in phase 1, and the Winamp cluster in phase 2. Known risk carried as a work item, not a blocker: overlapping skin windows + 16ms cursor polling can misroute clicks; when two frames intersect, drop the poll to 8ms, and only reach for an NSEvent local monitor if misroutes actually reproduce.

Q2 — PALETTE: yes, and the shape is: become the THIRD conformance consumer of the published notan-palette/1 artifact (grisaille and termviz are the others), with your existing in-process k-means as a declared lower tier, not a rival path. One correction to anything you may have read in the contract header: the producer EXISTS — RMPC-Auto-Theme ships the publisher, it writes $XDG_CONFIG_HOME/rmpc-auto-theme/palette/palette.json by atomic rename, and its stored capture decodes 9 roles / 7 verified pairs / 5 clusters with zero warnings against grisaille's merged decoder. Expose ONE PaletteService snapshot to the skin framework: { source: 'artifact'|'local'|'default', association: 'current-uri'|'retained'|'default', track: {uri, generatedAt}|null, roles (the nine v1 keys verbatim — never renamed, never partially filled), guarantees (verified_pairs copied verbatim, ALWAYS [] for local/default, exact-lookup helper only — the contract forbids inferring pairs or floors), clusters (share-ordered; hex is display-normative, oklch is interpolation-normative), and exactly one blessed polar-OKLCH lerp }. The honesty is structural: nothing in the API ever says "current art" or "now playing colors" — v1 proves URI association at generated_at, NOT occurrence freshness (A→B→A replays are valid), and the association field names that truthfully. Skins bind declaratively: each engine adapter maps engine slots to roles with per-slot fallbacks (WMP color slots, Winamp pledit/viscolor, your Headspace preset lerp); new slot vocabularies live in adapters, the nine roles never grow. Lift grisaille's merged consumer semantics wholesale — retention triple (latestAttempt / candidate / retained; failures never adopt or relabel retained colors), parent-dir watch attached before first read, serialized read + one dirty follow-up, 1/2/4/8/10s reattach continuing at cap — it's same-house code (src/palette-session.ts, src/palette-file.ts, docs/palette-runtime.md in grisaille). Honor MUSIC_UI_PALETTE_PATH; invalid value disables the artifact source with a diagnostic rather than falling back. Vendor the synthetic fixture set by pinned checksum, additive-only; re-run when the first genuine saturated-sleeve golden lands (Grisaille AI-IMP-019, pending an owner playback session). Two gotchas: debounce dual-source repaint (local k-means lands before the file watch — adopt once per song change, not twice), and do NOT publish your local extraction as a notan-palette artifact; that would make you an unratified second producer.

Q3 — TWO DECISIONS TO MAKE LOAD-BEARING BEFORE THE PANEL WRITES CODE, then process. (1) Skin JScript runs in a separate interpreter realm (QuickJS-WASM or interpreter-in-JS) — never host eval/Function on skin text — behind a copy-only membrane exposing nothing but the WMP object model; per-event-dispatch fuel budget, timer caps, WASM memory cap, repeated faults unload the skin; skin VFS resolves only normalized relative paths inside the bundle; res:// resolves ONLY to your bundled #132 reimplementation; http(s)/file from skin code rejected and logged. Your corpus is archive.org — every skin is untrusted input, including the zip layer: normalize entry names, reject traversal/symlinks, cap entries/sizes/compression ratio, extract to appdata/skins/<sha256>/. (2) Ship the engine as a Tauri-free package behind a HostAdapter (surfaces, input, clock, prefs, media model) with a CI rule enforcing zero Tauri imports — and build your pixel-diff oracle AS the second HostAdapter before the Tauri adapter grows features, so the seam is proven, not aspirational. That's also the honest answer to the owner's "layout engine for gris someday" musing: grisaille's SPEC already has a scene/host-adapter boundary, so a clean HostAdapter is all the optionality you need — don't design FOR gris, just keep the seam real. Process items worth adopting verbatim: a static scanner ranking object-model/#132 call-site frequency across the 337 parseable skins, committed as CSV, implemented in rank order; unimplemented APIs are generated stubs returning type-correct inert values that log once per (skin, api) into a coverage ledger CI renders — coverage becomes measured, never asserted; goldens content-addressed with a provenance sidecar (pinned Chrome, DPR=1, frozen clock, viz canvas stubbed), re-blessed only by explicit command; prefs one JSON file per skin content-hash, atomic rename, hard caps on keys/sizes — content-hash namespacing is what makes cross-skin pref abuse structurally impossible.
