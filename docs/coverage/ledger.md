# Coverage ledger

Generated by `npm run coverage` (`tools/corpus.mjs`, ENGINE D6.7) over 195 distinct WMP skins (342 archives).
Every skin runs headless through the real engine on the test host: load, attach, then a scripted minute
of play, pause, seek, resume, next and stop on the manual clock. Names and counts only, no skin art, no handler text.

A row is one (member, kind) pair. **skins** is how many of the distinct skins reached it, **hits** the
sum of their counts, **impl** the member's implementation in `src/engine/model/schema.js` (`-` for names
the schema does not have: an unknown member, an unknown tag, an unresolved resource or binding, a soft-fault site).
A `stub` row whose impl is `emulated` or `live` is a write or call the emulation accepts and drops: the window shows one
view, so `openView` and `closeView` of any other view are ledgered and not carried out (phase 3 opens more windows).
A hand-over of the one window to another view (a `currentViewID` write, or `openView` from a view with no area) is a view
switch (5F.6), reported in `corpus-load.txt`, not a ledger row. A name shared by a host object and a THEME attribute lists both impls.
Ledgered kinds: `stub`, `denied`, `unknown-member`, `unknown-tag`, `unresolved-binding`, `unresolved-res`, `soft-fault` and `cap`.
`live` and `emulated` members are not ledgered, so their demand is `api-frequency.csv` (static references), not this file.
Stubs are implemented in rank order (notan Q3).

A `soft-fault` row is a site where the realm or the runtime kept going after a fault: `handler <id>.<event>`,
`expr <id>.<attr>`, `script <file>`, `timer`, `call <name>`, `queue`, `jobs`, or a binding path. Its **hits** are **distinct reasons
per site, not occurrences**: the realm reports each (site, reason) pair once, so a handler that fails on every frame
adds 1 to its row. The occurrence count is the "realm soft faults" line of `corpus-load.txt`.
